# Nanites Dashboard — Frontend Notes

`frontend/nanites-dashboard.html` is the single source of the dashboard. The
build copies it to `dist/ui/index.html` and, alongside it, every image the page
references. The UI server (`src/ui/server.ts`) serves `/` plus a basename-only
static route for those images.

## Running it

```bash
npm run build     # copies the HTML + assets into dist/ui
npm run ui        # serves http://127.0.0.1:4700
```

For iteration, `npm run dev:ui` runs the TypeScript directly; the server falls
back to `frontend/nanites-dashboard.html` when no build exists.

## Themes

Three profiles, switched with the `data-theme` attribute on `<html>`:

| Theme | Character |
|---|---|
| `retro` | E-ink instrument panel. Paper + ink + one orange signal, with a day/night toggle. |
| `phosphor` | Green CRT terminal, gritty and angular. |
| `claude` | Modern minimal, quiet dark, sans headings. |

`retro` additionally carries `data-mode` of `day` or `night`. That is a
presentation preference, so it lives in `localStorage` under `nanites.retroMode`
rather than being written back to the profile. The theme choice itself **is**
persisted to the active profile via `POST /api/settings/profile`.

Themes are persisted by name, so a profile written by an older build can carry a
legacy name. `src/storage/profileDefaults.ts` maps those forward on read
(`cogitator` → `phosphor`, `anthropic` → `claude`) so the file still loads after
an upgrade. New names belong in `DASHBOARD_THEMES`.

### Adding a theme

1. Add the name to `DASHBOARD_THEMES` in `src/storage/profileDefaults.ts`.
2. Add a `[data-theme="<name>"]` block supplying the component variables. The
   components read a fixed set — `--bg`, `--panel-a`, `--panel-b`, `--border`,
   `--text`, `--text-muted`, `--accent`, `--accent-contrast`, `--success`,
   `--warn`, `--danger`, `--radius`, `--font-display`, `--font-body`,
   `--font-mono`, `--font-term`. A theme that sets all of those needs no
   component overrides.
3. Add a `.theme-option` button in the settings panel.
4. If it shows different chrome text, wrap that text in a `.retro-only` /
   `.phos-only` / `.claude-only` span and extend the visibility rules.

## Assets

Images are real files next to the HTML rather than inline base64 — they are
cacheable, diffable, and their provenance is visible in the repo. The build
copies any `png/gif/jpg/jpeg/svg/webp/ico` from `frontend/` into `dist/ui/`.

The logo marks are transparent silhouettes with white pixels, so one file tints
correctly under any theme. Swap one in by replacing the file and updating the
`src` attribute.

`skull-idle.png` / `skull-spin.png` back the cursor-evading skull in the header
and the resident-card avatars; `SKULL_IDLE_SRC` / `SKULL_SPIN_SRC` in the script
block swap between them. Behaviour is unchanged if the filenames are replaced.

## DOM ID contract (what each panel receives)

- **Live**: `#liveTerminal code` (append `.term-line` with `<span class="tag">[event]</span>` + `<span class="msg">…</span>`); `#dialTps`, `#dialTtft`, `#dialElapsed`.
- **Hardware**: `#residentGrid` — one `.panel.resident-card[data-resident="{model_id}"]` per loaded model, built by `buildResidentCards()` from the `loadedModels` array: `{id, quant, ctx, vram, level}`. `.vram-label` + `.gauge-fill` per card. `#hwOccupancy` (guardrail tier string), `#hwQueue`.
- **Registry**: `#leaderboardBody` rows `{model, score, params, tested}`; role filter `#roleTabs` (`all|reviewer|summarizer|coder`).
- **Cost**: `#tokenChart` (line, dates→tokens), `#roleChart` (doughnut Reviewer/Summarizer/Coder), `#statModel/#statDays/#statSaved/#statBook`, `#ledgerTerminal code` + `#pagerInfo/#pagerPrev/#pagerNext` rows `{ts, role, model, tin, tout, lat}`.
- **Health**: `#endpointPanel`, `#healthBadge` (text REACHABLE/DEGRADED/OFFLINE), `#healthPing`, `#healthRecovery`.
- **Settings**: `#cfgVram #cfgRam #cfgStorage #cfgTier #cfgPriceIn #cfgPriceOut #cfgNtfyUrl #cfgNtfyTopic #cfgNtfyToken #cfgDynamicModel #cfgEffort #cfgTtlS`, `#saveProfileMsg`. `#cfgTier` is the concurrency-pair override: value `""` = Auto (from specs), else an allowed `{max_parallel_models}x{num_parallel}` key like `2x2`; options repopulate from `allowedConcurrencyPairs(vram)` on profile load and on `#cfgVram` change. The save patch sends `concurrency_override` (`null` clears it); the server re-validates against the tier's allowed set.

## Alert levels (whole-card color)

`setAlertLevel(el, level)` with `level ∈ ok|warn|crit` toggles
`alert-ok/alert-warn/alert-critical` on the panel. Driven by endpoint status
(health) and per-model status (resident cards). Used on `#endpointPanel` and
every `.resident-card`.

## Conventions

- The dashboard script is one inline `<script>`. Keep the DOM IDs and data
  shapes stable; change the data source, not the contract.
- `#residentGrid` cards are generated by JS from real `list_models` /
  `get_loaded_model` data, not a hardcoded array.
- Sanitize anything returned to the dashboard: no absolute paths, no raw stack
  traces, trimmed shapes, structured errors. Secret fields go through
  `secretFor(remote, value)` so a LAN viewer never receives them in the clear.
- `restyleCharts(theme)` must still be called on theme switch (it repaints
  Chart.js colors and fonts).

## Do NOT touch

- Mascots are pure frontend presentation with zero data dependency:
  `#mascotLockup` (click → special animation) and
  `#hoverSkullZone/#hoverSkull` (the cursor-evader). No backend wiring. The
  resident-card mini avatars are cosmetic too.
